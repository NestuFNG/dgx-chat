package: self-contained container image

Adds a Dockerfile at the repository root that builds the web client in a first
stage and copies it into the runtime image, so running the container serves the
UI with no bind mounts. Verified on a real host: the image builds, /health
answers, the root page renders the app, and PID 1 runs as uid 10001 rather than
root.

A workflow publishes it to GitHub Packages on release, or manually from the
Actions tab. The compose file under server/ is unchanged and still mounts the
UI from the host for development.
